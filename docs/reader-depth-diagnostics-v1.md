# 개념별 진단 깊이 근거와 다음 확인 항목

1차 멘토링에서 제기된 “용어를 아는가보다 얼마나 깊이 아는가”에 대응하여,
기존 응답에서 사라지던 문항 유형·난이도별 근거를 보존한다.
기존 `reader-v1`은 가중 정답률이므로 쉬운 문항만 모두 맞힌 경우와 어려운 문항만
모두 맞힌 경우 모두 1.0이 될 수 있다. 1.0을 고급 숙련도의 증거로 해석하면 안 된다.

## 구현 범위

`POST /ml/reader-diagnostics`는 `/ml/reader-profile`과 같은 요청을 받는다.
새 API의 응답은 `reader-depth-evidence-v1`로 버전 관리한다.
기존 프로필 API, 추천 v1/v2 계산 및 응답은 변경하지 않는다.
아직 Backend의 호출·저장이나 Frontend 표시까지 연결된 기능은 아니다.

요청 예시는 `examples/assessment.json`의 snake_case 입력을 기존 DTO로 변환하거나,
기존 `/ml/reader-profile`에 보낸 camelCase 요청을 그대로 사용한다.
API 실행은 기존 `uv run uvicorn bookmatch_ml.api:create_app --factory` 명령을 사용한다.

## 산정 규칙

- 개념별 `observedScore`는 기존 설정의 난이도 가중 정답률과 같다.
  `sum(응답 점수 × 난이도 가중치) / sum(난이도 가중치)`로 계산한다.
- 각 개념에 easy/medium/hard × vocabulary/background_knowledge/comprehension의
  9개 셀을 반환한다. 셀 점수는 그 셀 응답 점수의 산술평균이다.
  같은 난이도이므로 기존 가중평균과도 일치한다.
- 각 셀에 응답 수, 만점 응답 수, 원본 `questionIds`를 반환한다.
  부분 점수는 그대로 유지한다. 미응시 셀은 `score: null`, 응답 수 0이다.
- `conceptId`와 `conceptTags`의 중복은 한 번만 센다. 여러 개념이 태그된 문항은
  해당 개념 각각의 근거이며, 개념별 응답 수를 합쳐 전체 응답 수로 해석하면 안 된다.
- 태그 없는 문항은 전체 응답 수와 `untaggedResponseCount`에 포함하지만 개념을 추측하지 않는다.
- `fullyObserved`는 9개 셀에 각각 1개 이상의 응답이 있다는 뜻이다.
  충분한 표본 수나 진단 신뢰성을 뜻하지 않는다.

## 다음 확인 규칙

`nextCheck`는 자동 출제가 아닌, 다음 진단을 위한 후보 셀이다.

1. 만점을 받지 못한 응답이 있는 셀을 먼저 복습·재확인 대상으로 제안한다.
   `reason: review_observed_gap`을 반환한다.
2. 그런 셀이 없다면 미응시 셀을 제안한다. `reason: unassessed`를 반환한다.
3. 각 그룹 안에서는 easy → medium → hard, 동일 난이도에서는 vocabulary →
   background_knowledge → comprehension 순서를 사용한다.
4. 모든 셀이 관측됐고 모두 만점이면 `nextCheck: null`이다. 숙련 완료를 선언하지 않는다.

순서는 버전으로 고정된 제품 규칙이다. 난이도 가중치의 크기나 YAML 키 순서에서 추론하지
않는다. easy/medium/hard 외 난이도 설정은 이 버전에서 거부한다. 새 난이도를 지원하려면
명시적 순서와 새 진단 버전을 함께 정의해야 한다.

| 동일 개념의 응답 예 | 기존 점수 | 다음 확인 |
|---|---:|---|
| 세 유형의 easy 문항 각 1개 만점 | 1.0 | medium vocabulary, 미응시 |
| 세 유형의 hard 문항 각 1개 만점 | 1.0 | easy vocabulary, 미응시 |
| 세 유형의 medium 문항 각 1개 0.5점 | 0.5 | medium vocabulary, 관측된 부족 부분 재확인 |

어려운 문제를 맞혔어도 쉬운 수준을 자동으로 통과 처리하지 않는다. 이후 문항 선택기가
이 제안을 활용할 때에는 해당 개념·유형·난이도의 **승인된 문항**이 실제 존재하는지 확인해야 한다.

## 해석 한계와 후속 작업

문항의 지정 난이도를 기준으로 응답을 분리한 것이며, 사람의 능력을 교정·검증한 등급이나
책 자체의 난이도가 아니다. 입력 계약에는 자기평가와 객관식 구분 및 평가 대상 개념의
주·보조 역할이 없다. 따라서 자기평가를 객관식 정답과 같은 신뢰도로 해석하거나,
복수 태그 문항의 오답을 모든 태그 개념의 부족으로 확정하면 안 된다.

Backend에서 응답 출처와 승인된 문항 메타데이터를 전달하고 이 결과를 화면에 연결하는
작업, 실제 사용자 응답으로 문항 난이도와 진단 타당성을 평가하는 작업이 남아 있다.
책의 깊이·방향 분류와 추천 순위 변경은 별도로 평가해야 한다.

## 검증

`tests/test_reader_diagnostics.py`는 동일 총점의 난이도별 구분, 부분 점수,
중복 태그, 미응시 보존, 입력 순서 독립성, 태그 없는 응답, 명시적 난이도 순서를 검사한다.
`tests/test_api.py`는 camelCase 변환, 기존 프로필 결과 보존, 중복 질문/잘못된 난이도의
422 응답을 검사한다. 합성 응답 검사는 계산 계약의 검증이며 진단 정확도의 증명이 아니다.
