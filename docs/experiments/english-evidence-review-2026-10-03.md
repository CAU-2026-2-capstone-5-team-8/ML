# 영문 근거 검토 자료 준비 — 2026-10-03

저장된 영문 목차 비교에서 증가한 연결을 원문과 함께 확인하기 위해
`compare-english-evidence --review-packet`을 추가했다. 기본 비교 결과는 그대로 두고,
명시적으로 요청한 검토 자료에만 원문·영문과 전체 근거 메타데이터를 넣는다.

## 실제 입력과 결과

- 기존 10권 영문 실험의 `book-evidence-v3.jsonl`: 666개 목차, 전부 원문·영문 쌍 존재.
- 원문·영문 사이 개념 연결이 달라진 목차는 328개다.
- 책/개념 쌍은 기존 13개에서 119개 추가, 1개 제거되어 131개다.
- 기존 한국어 머리말 실험의 98권 사본을 v3로 내보내 별도로 실행했다.
  머리말 발췌 2건을 준비했고, 저장된 영문은 둘 다 없다. 4,074개 목차도 영문이 없어
  paired 비교에서 제외된다. 이 사본의 비교값 0은 개념이 없다는 뜻이 아니다.
- 두 입력 모두 검토 자료를 두 번 생성하여 바이트 일치를 확인했다.
- 새 번역 API 호출은 0건이다. 자동 번역, 원문 변경, 운영 점수 변경은 하지 않는다.

검토 자료는 각 목차의 추가/제거 개념과 **책 전체에서 새로 추가/제거된 개념에 대한
근거인지**를 구분한다. 같은 개념이 다른 목차에 남아 있으면 한 행에서 사라져도
책 전체에서는 제거되지 않는다. 변경 없는 행과 미매칭 행도 포함하여 누락을 살펴볼 수 있다.
사람의 번역 판단, 매칭 판단, 검토자, 메모는 전부 null로 시작한다.

## 우선 확인할 8건

아래는 에이전트가 골라 확인한 후보이며, 328개 변경 항목 전체에 대한 정확도 평가나
사람의 검토 완료 결과가 아니다. 해당 근거 ID와 해시는 동명의 JSON에 남겼다.

1. **용어 사전 누락 후보 4건**: `Dot Product` 또는 복수형이 들어 있는 목차에서
   `inner product`가 연결되지 않는다. 현재 설정은 `inner product(s)`만 인식한다.
   한국어의 내적을 이런 영문 표현으로 옮긴 사례를 번역 오류로 일괄 처리하면 안 된다.
   다음 매칭 실험에서 동의어 후보를 별도 버전으로 평가할 수 있다.
2. **번역 의미 확인 후보 1건**: 스트랭 선형대수학의 미분 관련 목차가 영문에서는
   `Differences`로 시작한다. 이 항목은 여전히 `matrix`에 연결되므로 매칭 개수만
   보면 의미 변화가 드러나지 않는다. 원문 출처와 번역 작성 이력을 함께 확인해야 한다.
3. **문구 중복 처리 후보 3건**: 한영 혼합 원문에서 `vector`로 연결된 항목이
   영문에서는 더 긴 `vector space`로 연결된다. 이는 현재 중복 문구 처리와 단어
   경계 규칙의 영향을 받으며, 사라진 `vector`를 곧바로 번역 누락으로 볼 수 없다.

이 후보를 근거로 기존 번역이나 기본 사전을 수정하지 않았다. 새 용어 사전은
일반화된 합성 양성/음성 사례와 실제 입력 재비교를 거쳐 별도로 판단한다.

## 보관과 재현

원문을 포함한 자료는 ML의 무시된 로컬 경로
`data/reviews/english-evidence-review-20261003/`에만 저장했다:

- `toc-review.json` / `toc-review-replay.json`
- `korean-prose-v3.jsonl`
- `prose-review.json` / `prose-review-replay.json`

Git에는 원문을 제외한 이 보고서와 동명의 집계 JSON만 포함한다. 실행 예:

```bash
uv run bookmatch-ml compare-english-evidence \
  --input <book-evidence-v3.jsonl> --review-packet \
  --output data/reviews/english-review.json
```

항상 새 출력 파일을 사용한다. 기존 파일 덮어쓰기와 변조된 v3 입력은 거부하며,
CLI가 입력 해시를 기록한다. 검토 자료에 사람이 값을 작성해도 자동으로 gold label이나
추천 정책으로 가져오는 경로는 없다.
