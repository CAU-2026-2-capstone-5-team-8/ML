# 원문·저장 영문 목차 비교, 2026-10-03

기존 10권의 목차 번역을 그대로 읽어 동일한 설정으로 양쪽을 비교했다. 번역 생성이나
서비스 반영 없이 재현 가능한 비교 경로와 v3 reader를 추가했다. 기존 계정/진단 PR에
포함된 기능 전체를 가져오지 않고 필요한 canonical 영문 필드만 별도로 연결했다.

```bash
uv run bookmatch-ml compare-english-evidence \
  --input ../Data-Pipeline/data/experiments/english-evidence-comparison-20261003/book-evidence-v3.jsonl \
  --output data/reports/english-comparison.json
```

## 비교 조건

- 원문은 `text`, 영문은 저장된 `en_text`다. 생성하거나 원문으로 대체하지 않는다.
- 동일한 책, 동일한 목차 행, 동일한 features/graph/matching 설정을 양쪽에 적용한다.
- 목차 외 소개·제목·본문은 비교 대상에 넣지 않는다. 미번역 또는 설정된 주제가 없는 행은
  양쪽 비교에서 제외하고 이유를 기록한다. 모호한 매칭도 따로 기록한다.
- 결과에는 원문/영문 해시, 근거 ID, 양쪽 매칭, 추가/제거된 개념이 남는다. 출력에는 원문이나
  번역 문장 전체를 넣지 않는다. `human_translation_review`는 null,
  `evaluation_status`는 `not_evaluated`다.
- 입력 해시가 실행 중 달라지면 실패하고, 기존 출력 파일을 덮어쓰지 않는다.

## 실제 관찰

| 항목 | 원문 | 저장 영문 |
| --- | ---: | ---: |
| 책 수 | 10 | 10 |
| 비교 목차 행 | 666 | 666 |
| 개념이 매칭된 책 | 4 | 10 |
| 책·개념 연결 | 13 | 131 |

행별 번역 유무를 확인했고 666행 모두 비교 대상이었다. 전체 결과 두 번이 바이트 단위로
같고, 입력의 영문 필드를 제외한 원본 책·문서·목차·출처는 원래 Discovery 자료와 같다.
[측정·해시 기록](english-evidence-comparison-2026-10-03.json)에 각 설정과 입력, 기존 번역
실행 기록, 비교 출력의 해시 및 책별 집계를 남겼다. 전체 행별 결과는 로컬 ignored
`Data-Pipeline/data/experiments/english-evidence-comparison-20261003/comparison.json`에 있다.

이 실행의 번역 API 호출은 0회다. 기존 번역 비용·정확도·추천 품질을 새로 검증한 것은
아니다. 매칭 증가가 오역이나 과도한 개념 확장에 의한 것인지는 사람의 검토가 필요하다.
기존 영문 필드 작성 실험의 결과를 최신 코드에서 재현한 것이며, 일반화된 정확도 지표가 아니다.

이 10권 사본에는 영문 본문뿐 아니라 분석할 서문/장 본문도 없다. 새로 수집한 한국어
머리말 2건은 다른 실험 사본에 있고 아직 영문이 없다. 따라서 목차 연결 개선을 본문
난이도 개선으로 보고하지 않는다. 현재 기본 프로필·랭킹·언어 진단은 계속 원문을 사용한다.

## 검증과 후속

전체 ML 테스트 342개, Ruff 검사·포맷 통과. 공유 합성 fixture로 v3 import, 공백 보존,
발췌/권리 정보, 변조·누락·빈 번역 거절, 구버전 위장 거절과 누락 번역의 비교 제외를 검사했다.
Data-Pipeline은 476개 검사와 실제 v1/v2 바이트 호환성, v3 CLI 출력을 확인했다.

ML reader를 먼저 적용한 뒤 v3 exporter를 사용한다. 기존 PR #32의 영문 필드 변경을
통합할 때는 v1에 `en_text`를 다시 넣지 말고 이 계약과 원문 보존 규칙을 유지해야 한다.
다음 단계는 추가/제거된 매칭의 사람 검토와 새 머리말의 검토 가능한 영문 표본 확보다.
이 보고서를 근거로 운영 추천을 영문 우선으로 전환하지 않는다.
