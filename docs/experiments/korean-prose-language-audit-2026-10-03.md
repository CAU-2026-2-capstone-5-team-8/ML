# 한국어 본문 언어 진단, 2026-10-03

`audit-prose-language`는 실제 canonical 본문을 현재 baseline으로 분석했을 때의 결과와 언어
주의 사항을 나란히 기록한다. 원문과 추천 점수를 바꾸지 않는 독립 진단 명령이다.

```bash
uv run bookmatch-ml audit-prose-language \
  --data-dir ../Data-Pipeline/data/experiments/korean-prose-pilot-20261003/replay1/processed \
  --baseline-language en \
  --output data/reports/korean-prose-language-audit.json
```

`--baseline-language`는 사용자가 명시하는 분석 기준 언어이며 모델의 언어를 변경하거나
감지하는 옵션이 아니다. 현재 feature config는 영어 개념 별칭과 선수지식 표현을 사용하므로
이 실험에서는 `en`을 명시했다. `en`과 `eng`, `ko`와 `kor`를 같은 표기로 처리한다.
도서의 언어는 문서 자체의 언어 검증을 대신하지 않으므로 `declared_book_language`라고 표기한다.

각 본문 행에는 문서·출처 ID, URL, 범위, 해시, 문자 수, Unicode 글자 기준 한글/라틴/기타
개수, 현재 baseline의 결과 또는 제외 이유가 담긴다. 한글 비중의 분모는 공백·숫자를 제외한
글자 수다. 영어 기준 입력에 한글이 있으면 분량과 무관하게 검토 표시를 남기며, 이것만으로
문서 언어 또는 분석 불가를 판정하지 않는다. 소개·목차는 본문 행으로 바꾸지 않는다.

점수의 타당성은 언제나 `evaluation_status=not_evaluated`로 남긴다. 도서 언어가 기준 언어와
일치해도 품질 검증 통과를 뜻하지 않는다. 세 개의 사람 검토 필드는 비워 두며 정답이나
난이도 라벨을 생성하지 않는다. 입력 네 파일과 설정의 해시를 기록하고 기존 출력 덮어쓰기를
거절한다. 같은 입력·설정·언어는 동일한 보고서를 만든다.

## 실제 데이터 결과

기존 98권, 목차 83권의 별도 사본에서 본문 유형 문서를 가진 책은 2권이다. 두 문서는 모두
공식 머리말의 일부이며 완전한 머리말이나 장 본문으로 표시하지 않는다.

| 문서 | 문자 / 토큰 | 현재 baseline 관찰 |
| --- | --- | --- |
| 현대 선형대수학 머리말 발췌 | 1,362 / 320 | 계산은 되지만 설정된 개념 별칭·선수지식 매칭 모두 0 |
| 기초선형대수 머리말 발췌 | 230 / 49 | 50토큰 기준 미달, 점수 없음 |

첫 문서의 글자 중 한글 비율은 약 87.5%, 두 번째는 약 99.4%다. 첫 문서의 lexical 점수
0.0109375와 개념 밀도 0을 '쉬운 책' 또는 '개념이 없는 책'의 근거로 해석할 수 없다.
이는 영어 중심 설정을 한국어 원문에 적용한 결과일 뿐이다. 새 짧은 발췌가 늘었다고 해서
난이도 평가 가능 도서가 늘어난 것도 아니다.

[전체 측정 보고서](korean-prose-language-audit-2026-10-03.json)는 원문을 담지 않는다.
독립 두 번의 canonical 재생성 후 진단 보고서도 바이트 단위로 같았으며, v2 importer가
98권과 두 발췌 범위를 읽는 것을 확인했다. 기존 점수 계산·프로필·랭킹 경로는 수정하지 않았다.

전체 테스트 335개, Ruff 검사·포맷 통과. 새 검사 10개는 한국어/영어 선언 불일치,
미확인 언어, 짧은 발췌, 본문 부재, 결정적 출력과 기존 파일 보존을 다룬다.

## 다음 판단

1. 더 긴 실제 본문을 확보하되 풀이·정오표는 본문 표본에서 제외한다.
2. 기존 영문 분석 필드 작업을 통합할 때 원문과 번역의 길이·개념 포착 차이를 비교한다.
   이 보고서는 현재 main의 원문 `text`만 검사하며 미완성 번역 브랜치를 가져오지 않는다.
3. 한국어 원문의 표현을 이해하는 사람의 상대 난이도 라벨을 확보한 뒤 점수 타당성을 평가한다.

정답 라벨 없이 일치율·상관계수·한국어 난이도 개선을 주장하지 않는다. 서비스 DB와 실행 중인
추천 흐름에는 이 실험 데이터를 반영하지 않았다.
